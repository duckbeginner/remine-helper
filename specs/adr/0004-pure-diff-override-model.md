# ADR-0004: 최소 차분(Pure Diff) 오버라이드 모델

- **상태 (Status)**: `ACCEPTED`
- **결정 일자**: 2026-09-18
- **결정자 (Deciders)**: 프로젝트 아키텍트 (@duckbeginner) & AI 페어 프로그래머
- **영향 범위**: `schedule-overrides.json`, Ops 포털 저장 엔진(`docs/ops.js`), `mergeSchedulesV2`, 데이터 수집 파이프라인

---

## 1. 컨텍스트 및 문제 정의 (Context)
- 관리자가 일정 1건의 제목이나 링크 하나만 수정했을 때, 해당 일정의 모든 속성(시작시간, 종료시간, 장소, 카테고리 등)을 통째로 오버라이드 객체에 전체 덤프(Full Dump)하는 과거 방식은 다음과 같은 치명적인 결함을 유발했습니다:
  1. 원본 수집처(Blip, Mnet Plus 등)에서 일정의 장소나 시간이 공식적으로 변경되더라도, 전체 덤프된 과거 오버라이드 데이터가 이를 무조건 덮어써 최신 공지 반영이 영구 차단됨.
  2. 수정하지 않은 불필요한 속성들까지 전부 저장되어 `schedule-overrides.json` 파일의 용량이 기하급수적으로 비대해지고, Git 동시 편집 충돌 위험이 급증함.

---

## 2. 고려된 대안들 (Alternatives Considered)
1. **대안 A: 전체 객체 스냅샷 덤프 (Full Object Dump)**
   - *장점*: 병합 로직이 단순하여 원본 객체를 오버라이드 객체로 단순 치환 가능.
   - *기각 사유*: 원본 제공처의 부분 업데이트(시간 연기, 장소 변경 등)를 영구적으로 흡수하지 못하는 데이터 침식 발생.
2. **대안 B: 이벤트 소싱 / 변경 로그 모델 (Append-only Change Log)**
   - *장점*: 모든 변경 이력의 시계열 추적 가능.
   - *기각 사유*: GitHub Gist 정적 파일 환경에서 매 빌드마다 이벤트 리플레이 연산 오버헤드가 크고 관리 복잡도가 과도함.
3. **대안 C (선택): 최소 차분(Pure Diff) 속성 단위 오버라이드 모델**
   - *장점*: 원본과 실제로 달라진 속성(Key)만 저장하므로, 오버라이드되지 않은 필드는 외부 공식 변경사항을 실시간 그대로 흡수함. 파일 크기를 최소화하며 원본 복구(Revert)도 키 삭제만으로 간단히 완결.

---

## 3. 최종 결정 사항 및 핵심 규칙 (Decision & Rules)
1. **최소 차분(Pure Diff) 저장 원칙**:
   - `schedule-overrides.json`의 `sourceOverrides[id]`에는 **원본과 실제로 달라진 속성(Key)만 선별 저장**한다.
   - 예: 제목만 바뀐 경우 `{ "title": "수정된 제목" }`만 저장하고, `startTime`, `location` 등 변경되지 않은 필드는 절대 저장하지 않는다.
2. **사전 정규화 후 Diff 판정**:
   - 단순 문자열 공백, `undefined` vs `""`, 시간대 오프셋(`Z` vs `+00:00`) 표기 차이로 인한 허위 차분(False Positive)을 방지하기 위해, 비교 전 표준 정규화(Normalization)를 거쳐 실제 내용 변경 여부를 엄격히 판정한다.
3. **원본 복구(Revert) 메커니즘**:
   - 관리자가 수정을 취소할 경우 해당 키를 오버라이드에서 완전히 `delete`하여 원본 수집 데이터로 즉시 회귀할 수 있도록 보장한다.
4. **병합 우선순위 (Merge Precedence)**:
   - 병합 시 `원본 수집 데이터` < `sourceOverrides (차분 필드 덮어쓰기)` < `customSchedules (신규 추가 일정)` 순으로 엄격히 합성한다.

---

## 4. 기대 효과 및 불변 제약 (Consequences & Invariants)
- **기대 효과**:
   - 공식 제공처의 일정 시간 연기, 취소, 장소 정정 등 긴급 업데이트의 실시간 무손실 반영 보장.
   - `schedule-overrides.json` 파일 용량 70% 이상 감축 및 동시성 충돌 방지.
- **불변 제약 (Invariants)**:
   - Ops 포털 및 오버라이드 저장 모듈은 원본과 동일한 값을 가진 속성을 커밋 전 반드시 정리(Prune)해야 하며, 원본과 완전 동일한 덤프 객체가 `sourceOverrides`에 등록되는 것을 금지한다.
